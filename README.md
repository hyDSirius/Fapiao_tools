# fapiao · 发票金额统计工具

一个面向 Windows PowerShell 的本地命令行工具：将当前目录中的 OFD 发票、行程单转换为 PDF，识别 PDF 中的合计金额，并打印逐份明细和人民币总额。

```powershell
fapiao
```

## 功能

- 读取当前目录的 `.pdf`、`.ofd` 文件，扩展名不区分大小写，不扫描子目录。
- 自动转换 OFD，保留原文件，重复运行时复用转换结果。
- 识别普通发票的价税合计、航空行程单的合计等金额字段。
- 根据文件内容和发票号码去重，支持负数红字金额。
- 列出识别失败或需要人工核对的文件，区分完整总额与已识别金额小计。
- 文档转换和统计均在本机完成，不上传文件；首次安装依赖需要联网。

## 环境要求

- Windows 与 PowerShell。
- Python 3.10 或以上，且 `python` 命令可用。

当前安装脚本和命令入口面向 Windows，其他系统尚未验证。

## 安装

克隆或下载本仓库，在项目根目录打开 PowerShell，执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

安装脚本会：

1. 在项目目录创建 Python 虚拟环境 `.venv`。
2. 安装 `requirements.txt` 中的依赖并检查依赖是否完整。
3. 将项目目录添加到当前用户的 `PATH`，使 `fapiao` 命令可以在其他目录使用。

安装完成后重新打开 PowerShell。如果使用 Windows Terminal 或 VS Code 内置终端，可能需要退出整个终端程序后再重新打开，以加载新的 `PATH`。

请保留项目目录及 `.venv`。如果移动项目目录，需要重新配置 `PATH`，并建议重新创建虚拟环境。

## 使用

在存放发票的目录中打开 PowerShell：

```powershell
fapiao
```

也可以指定目标目录，相对路径以调用命令时所在的目录为基准：

```powershell
fapiao .\invoices
```

查看命令帮助：

```powershell
fapiao --help
```

如果尚未配置 `PATH`，可在项目根目录直接调用入口：

```powershell
.\fapiao.cmd .\invoices
```

不传目录参数时，统计的是调用命令时的当前目录。

以下为输出示例，文件名与金额仅作演示：

```text
[转换] 行程单.ofd -> 行程单.pdf
[计入] 行程单.pdf 第1页  ￥120.00
[计入] 保险发票.pdf 第1页  ￥35.00

计入 2 张，跳过重复 0 份，待核对 0 份
全部发票总额：￥155.00
```

## 实现方式

### OFD 转换为 PDF

转换由 [easyofd](https://github.com/renoyuan/easyofd) 完成：读取 OFD 文件并进行 Base64 编码，调用 `OFD.read()` 解析，再调用 `OFD.to_pdf()` 生成 PDF。

生成后使用 [PyMuPDF](https://github.com/pymupdf/PyMuPDF) 检查 PDF 是否可打开且包含页面，并在 PDF 元数据中记录源 OFD 的 SHA-256 哈希。下次运行时，只有哈希匹配的本工具转换结果才会被复用。

默认保存为同名 `.pdf`。已有同名文件且无法确认属于本工具的对应转换结果时，会尝试 `.ofd.pdf` 等其他名称，不覆盖已有文件。原始 OFD 始终保留。

### 金额识别与汇总

使用 PyMuPDF 提取 PDF 中的文字及位置，结合金额标签和坐标寻找对应的数字，而非简单选取页面中的最大金额。

- 普通发票优先读取“价税合计（小写）”，避免把不含税的“合计”当作最终金额。
- 航空行程单读取“合计”，支持金额位于标签下方的表格布局。
- 其他可识别标签包括“总计”“实付金额”“支付金额”。
- 统一处理数字间空格、全角字符和负号等文本差异。
- 使用 Python `Decimal` 累加金额，避免二进制浮点数带来的金额计算误差。

航空行程单的票价、税额和单列保险费不会再次叠加到合计金额中；单独的保险发票仍作为独立发票计入。

### 重复票据识别

先使用 SHA-256 跳过内容完全相同的 PDF，再根据发票号码判断重复票据：

- 新版电子发票使用 20 位发票号码。
- 旧版发票使用明确标注的发票代码与 8 位发票号码组合。
- 号码根据“发票号码”“发票代码”标签及数字位置识别，避免将页面其他位置的银行账号当作发票号码。
- 同一发票号码对应不同金额时，提示人工核对。

未能识别号码的文件仍可统计金额，但不同内容的文件之间无法保证去重，请检查输出明细。

## 适用范围与限制

- 适用于含可提取文字的电子发票和行程单。工具不内置 OCR，纯扫描 PDF 需要先进行 OCR。
- 非航空行程单需有可识别的总计或支付金额标签；特殊版式可能需要补充识别规则。
- 多页 PDF 逐页识别。附录或明细续页没有可识别总额时会提示核对，应先拆分相关页面。
- 同页存在多个已标注的发票号码，或多个不同的候选合计金额时，需要人工核对或拆分文件。
- 无法读取、已加密、损坏或无法确定金额的文件会标为“待核对”。此时只打印“已识别金额小计”，退出码为 `1`；全部成功时退出码为 `0`。
- OFD 转 PDF 属于重新绘制，字体或复杂版式可能出现差异。转换后的 PDF 不继承原始 OFD 的数字签名效力，原始文件应保留以供验签。
- 源 OFD 改变后，旧的转换 PDF 会保留。请移走过期票据，避免它们继续参与统计。

## 项目结构

```text
.
├── fapiao.py           # 文件扫描、OFD 转换、金额识别与去重汇总
├── fapiao.cmd          # Windows 命令入口
├── install.ps1         # 虚拟环境、依赖与用户 PATH 配置
├── requirements.txt    # Python 依赖
└── tests/              # 本地测试目录，已加入 .gitignore
    ├── test_fapiao.py   # 自动化测试代码
    └── fixtures/       # PDF / OFD 验证样本
```

## 测试

测试代码和样本统一存放于 `tests/`，整个目录已加入 `.gitignore`，默认不提交到 Git。以下命令适用于本地保留了该目录的开发环境。

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

测试覆盖 OFD 转换与复用、已有 PDF 保护、金额识别、负数与零金额、重复票据、银行账号与发票号码区分，以及异常文件处理。样本相关测试依赖 `tests/fixtures/` 目录中的 PDF / OFD 文件。

手动验证样本目录：

```powershell
fapiao .\tests\fixtures
```
